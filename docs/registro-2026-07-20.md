# Registro de atividades — 20/07/2026

## Resumo

Foi realizada uma revisão e uma refatoração do projeto de análise do Campeonato Brasileiro, com foco em engenharia de dados, qualidade, reprodutibilidade e compatibilidade com o Power BI.

## O que foi feito

### Pipeline

- O ETL deixou de depender exclusivamente do notebook.
- Foram criados módulos em `src/` para:
  - leitura robusta dos CSVs;
  - normalização de encoding e nomes de clubes;
  - construção da tabela fato;
  - cálculo de acumulados e rankings;
  - análise da tese da 8ª rodada;
  - validação da qualidade dos dados;
  - cálculo de estatísticas e intervalos de confiança.
- Foi criada a execução via comando:

```bash
python -m src.pipeline --allow-incomplete
```

### Qualidade dos dados

- Foi criado um modo estrito que interrompe a execução diante de temporadas incompletas.
- Foi criado o modo `--allow-incomplete`, que gera os arquivos e marca as limitações.
- Os nomes de clubes foram padronizados, incluindo acentos, aliases e textos com mojibake.
- A tabela fato passou a possuir `partida_id` e `partida_realizada`.
- A partida Chapecoense × Atlético-MG de 2016, que está sem placar na fonte, não recebe pontos artificialmente.
- A temporada de 2024 permanece marcada como incompleta porque a fonte possui apenas 283 partidas.

### Estatística

- O teste t aplicado a uma variável binária foi removido.
- Foi implementado teste binomial para a proporção de confirmações da tese.
- Foram preservados os intervalos de confiança usados pelo Power BI.
- A análise passou a considerar somente temporadas válidas para inferência.
- A correlação entre investimento e pontos continua disponível, acompanhada de amostra e p-value.

### Documentação e dependências

### Arquivos removidos ou reorganizados

- `notebooks/UltimateVersion_backup.ipynb` foi removido por ser um backup redundante e conter código inválido.
- `notebooks/README.md` passou a explicar que o ETL principal é executado pelo módulo Python.

- Os arquivos brutos originais foram preservados e não são sobrescritos pelo pipeline.

## Banco de dados e nuvem

Atualmente, o projeto **não possui banco de dados na nuvem**.

Não foram encontrados conectores ou configurações para PostgreSQL, MySQL, MongoDB, Supabase, Firebase, API ou outro serviço de armazenamento remoto.

O fluxo atual é:

```text
dados/raw/*.csv
        ↓
python -m src.pipeline --allow-incomplete
        ↓
dados/processed/*.csv
        ↓
Power BI Desktop
```

Portanto, os dados estão armazenados localmente no repositório e o Power BI precisa encontrar os CSVs no caminho local configurado.

Se algum arquivo não estiver carregando no Power BI, verifique principalmente:

1. se a fonte aponta para `dados/processed/` da cópia atual do projeto;
2. se o delimitador correto foi selecionado;
3. se a codificação está como UTF-8/65001;
4. se o Power BI foi atualizado para reconhecer as colunas novas;
5. se as medidas antigas ainda apontam para nomes de colunas removidos ou renomeados.
